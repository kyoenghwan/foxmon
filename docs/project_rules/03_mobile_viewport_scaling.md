## 1. 핵심 원칙 (절대 준수) ⭐⭐⭐⭐⭐

> **"425px는 스마트폰 세로모드의 최적화 기준 화면이다. 425px 미만의 모든 디바이스에서는 CSS zoom을 통해 화면 내 모든 컴포넌트(로고, 폰트, 이미지, 패딩, 마진, 그리드 등)가 비율대로 균일하게 축소되어야 한다. 어떤 요소도 예외 없이 동일한 비율로 축소되며, 일부만 축소되거나 일부만 유지되어 레이아웃이 깨지는 현상을 절대 허용하지 않는다."**

### 1.1 절대 상수 (Immutable Constants)

| 상수명 | 값 | 역할 | 수정 가능 여부 |
|---|---|---|---|
| `MOBILE_TRIGGER` | `425` | 스케일링 발동 기준점 (이 값 미만에서 zoom 작동) | ❌ 절대 금지 |
| `MOBILE_RENDER_WIDTH` | `390` | 실제 렌더링 기준 너비 (축소 비율 완화용) | ⚠️ 사용자 승인 필요 |

### 1.2 줌 계산 공식 (Zoom Formula)

```
화면 너비(vw) < 425px 일 때:
  zoom = vw / MOBILE_RENDER_WIDTH (= vw / 390)
  width = 390px (고정)

화면 너비(vw) >= 425px 일 때:
  zoom = 적용 안 함
  width = 일반 반응형 (Tailwind max-w 클래스 사용)
```

### 1.3 기기별 줌 비율 참조표

| 기기 너비 | 줌 비율 | 체감 축소 |
|---|---|---|
| 424px | 1.087 (미세 확대) | 거의 원본 |
| 400px | 1.026 (미세 확대) | 거의 원본 |
| 390px | 1.000 | 원본 그대로 |
| 375px (iPhone SE) | 0.962 | 약 4% 축소 |
| 360px (Android) | 0.923 | 약 8% 축소 |
| 320px (구형) | 0.821 | 약 18% 축소 |

## 3. 금지 사항 (Never Do) ❌

```text
❌ 절대 금지 목록:
- MaxWidthWrapper.tsx의 MOBILE_TRIGGER(425) 값을 임의 변경하는 행위
- MaxWidthWrapper.tsx의 줌 스케일링 useEffect 로직을 제거하거나 비활성화하는 행위
- 개별 컴포넌트에서 @media (max-width: 424px) 등으로 425px 미만 전용 CSS를 작성하는 행위
  (줌 스케일링과 충돌하여 이중 축소 또는 레이아웃 깨짐 발생)
- viewport meta 태그를 JS로 동적 조작하는 행위 (CSS zoom 방식과 충돌)
- 425px 미만에서 특정 컴포넌트만 따로 크기를 고정하는 행위
  (일괄 비율 축소 원칙 위반)
- transform: scale() 방식으로 스케일링을 대체하려는 행위
  (레이아웃 박스에 영향을 주지 않아 스크롤/fixed 요소 깨짐 발생)
```

## 6. 기술적 배경 (참고)

### 왜 CSS zoom인가?
- **`transform: scale()`**: 레이아웃 박스에 영향 없음 → 스크롤 깨짐, fixed 요소 위치 이탈
- **`viewport meta 태그 동적 변경`**: 브라우저 Text Autosizing 정책과 충돌, 일부 요소만 축소되는 현상 발생
- **`CSS zoom`** ✅: 레이아웃 자체를 축소하여 모든 자식 요소가 균일하게 비율 축소됨. Chrome/Safari/Edge/Firefox(126+) 지원.

### 왜 425px인가?
- 스마트폰 세로모드에서 가장 넓은 일반적 뷰포트 (iPhone 14 Pro Max: 430px, Galaxy S24: 412px)
- 425px에 최적화된 디자인을 기준으로 하위 디바이스에서 비율 축소하면 모든 모바일 커버 가능

### 왜 390px 렌더링인가?
- 425px 기준 렌더링 시 375px 폰에서 zoom 0.882 → 폰트가 약 12% 축소되어 가독성 저하
- 390px 기준 렌더링 시 375px 폰에서 zoom 0.962 → 약 4% 축소로 가독성 양호
