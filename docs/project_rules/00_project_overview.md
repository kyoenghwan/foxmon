## 프로젝트 전역 제약 사항

- **배너 UI/UX 규칙**: 모든 배너(본문 가로 배너 및 사이드 세로 배너)는 반응형 동기화 시스템을 통해서만 크기 조절이 가능합니다. 임의로 단일 배너의 크기를 변경하는 것은 레이아웃 붕괴를 초래하므로 금지됩니다.
- **모바일 뷰포트 스케일링 규칙**: 425px는 스마트폰 세로모드 기준 화면입니다. 425px 미만에서는 `MaxWidthWrapper.tsx`의 CSS zoom 스케일링이 모든 컴포넌트를 비율대로 일괄 축소합니다. 이 로직의 상수(`MOBILE_TRIGGER=425`)를 임의 변경하거나, 개별 컴포넌트에서 425px 미만 전용 미디어 쿼리를 추가하는 것은 금지됩니다.
- **이미지 업로드 규칙**: 플랫폼 내부의 모든 이미지 저장/수정 폼은 스토리지 업로드 전 무조건 WebP(압축 품질 80, 애니메이션 GIF인 경우 프레임 유지) 포맷으로 변환해야 합니다.
- **닫기 버튼 UI 규칙**: 사용자 인터페이스 전반에 걸쳐 사용되는 모달, 팝업, 다이얼로그 등의 닫기 버튼은 아이콘(예: X 아이콘) 단독으로 사용하지 않고, 반드시 명시적인 **"닫기"** 텍스트를 사용해야 합니다. 사용자가 닫기 기능을 직관적으로 인지할 수 있도록 보장해야 합니다.

## 범용 지침과의 관계

- **절대 불변**: 8-Atom 체계, 8대 절대 원칙
- **우선 적용**: 이 폴더(`docs/project_rules/`)에 존재하는 프로젝트 특수 지침이 범용 지침(`.rules/`)보다 우선 적용됩니다.
- **충돌 해결**: 원자 순수성을 훼손하지 않는 선에서 프로젝트 지침의 레이아웃/비즈니스 제약을 최우선으로 준수합니다.
