# 폭스몬 Atom 설계

폭스몬 전용이다. 상대 경로는 저장소 루트 기준이며 작업·검증은 AGENTS.md를 따른다.

1. docs/project_map.yaml, 관련 docs/processes 문서와 실제 호출자를 찾는다. src/atoms뿐 아니라 atoms, lib, actions, app/api를 함께 검색한다.
2. DB 작업은 관련 docs/db 문서·supabase/migrations·실제 타입을 대조한다. 현재 통합 docs/db/schema.sql은 없으며 운영 적용 여부를 추측하지 않는다.
3. 기존 FA/QA/OA/RA를 재사용한다. RA는 외부 의존성 없는 계산, QA는 조회, OA는 부수효과, FA는 흐름 조립이다. DA/CA/TA/EA는 기존 역할을 보존한다.
4. 보호 데이터 처리 전에 기존 서버 세션과 소유권·역할 검증을 재사용한다. 입력 userId나 클라이언트 역할을 인증 증거로 신뢰하지 않는다. NextAuth와 Supabase 인증의 연결을 확인하고 관리자 클라이언트의 RLS 우회를 고려한다.
5. 여러 쓰기가 하나의 결제/저장 결과라면 단일 DB 트랜잭션을 우선 검토한다. 순차 HTTP 요청은 트랜잭션이 아니다. 동시 요청, 중복 제출, 실패 후 상태를 검증한다. 실제 보상이 필요한 경우에만 복구 정보를 반환하며, 보상 실패를 성공으로 표시하지 않는다.
6. UI는 기존 서버 진입점을 호출하고 결과로 상태·라우팅을 갱신한다. 새 직접 DB 쓰기를 UI에 추가하지 않는다. 중복 제출 잠금만으로 서버 측 멱등성이나 동시성 안전을 주장하지 않는다.
7. 새 원자나 경로는 색인을 갱신한다. 기존 결과 계약을 필요 없이 일괄 변경하지 않는다. 템플릿은 참고하되 전체 input 로깅·가짜 rollback·별도 YAML 승인 절차를 복제하지 않는다.

확인할 반례: 권한 없는 호출, 타인 ID, 잔액 부족, 동시 차감, 거래 로그 저장 실패, 외부 알림 실패. 실제 데이터를 변경하는 검증은 별도 권한과 복구 조건을 확인한다.
